# Шаблоны сообщений бота — дизайн

Дата: 2026-09-21 · Статус: черновик на ревью · Репозиторий: NRW-Bot (бэкенд и редактор в боте). Страница «Уведомления» во фронтенде (NRW-MiniApp) — отдельная работа по контракту из `docs/api/`.

## 1. Контекст и проблема

Бот сам отправляет пользователям сообщения по событиям (оплата, истечение подписки, бонусы, автоплатёж, напоминания). Все тексты зашиты в код (`app/services/notification_service.py`); чтобы поменять слово или поставить эмодзи, нужна правка кода и деплой. Механика кастомных эмодзи подготовлена (`app/emoji.py`, команда `/emojiid`), но ID прописываются в коде, а в текст сообщения их вставить из админки нельзя.

Владелец хочет **свободно редактировать эти сообщения** (включая кастомные эмодзи и форматирование) из админки и из бота, знать, какие именно сообщения существуют, и включать/выключать их.

Состояние сегодня:
- 14 функций `notify_*`; три из них (`winback`, `abandoned_payment`, `welcome_nudge`) отправляются с кнопкой; отправка через общий `_safe_send` (ловит ошибки, один повтор при flood-control).
- Бот создаётся с `parse_mode=HTML`, поэтому все тексты — фактически HTML Telegram.
- Во фронтенде уже написана страница «Уведомления» под эндпоинт `GET /cabinet/admin/notifications/templates` с типом `NotificationTemplate {key, group, title, trigger, template, variables: string[]}`; бэкенда для неё нет.

## 2. Цели и не-цели

**Цели**
- Тексты автоматических сообщений хранятся в БД и редактируются из веб-админки и из бота, изменения действуют сразу.
- Заводские тексты остаются в коде как запасной вариант: без правок поведение бота не меняется ни на символ.
- Ошибка в шаблоне никогда не приводит к потере уведомления.
- Кастомные эмодзи и форматирование вставляются из редактора; предпросмотр и тестовая отправка.

**Не-цели (v1)**
- Многоязычность (решение владельца: только русский; колонки языка нет).
- Тексты приветствия, правил, меню и ответов обработчиков (`handlers/*`, словарь `TEXTS` в `start.py`), сообщение «триал выдан».
- Условия и время отправки (например, «напоминать за 5 дней»), логика в шаблонах (Jinja), A/B-тесты.
- История версий шаблона (только «кто и когда изменил последним»).
- Реализация страницы во фронтенде.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Объём | Только автоматические сообщения по событиям (15 событий) |
| Языки | Только русский |
| Где редактировать | Веб-админка **и** бот (`/admin` → «✉️ Сообщения») |
| Хранение | Таблица в БД для правок + реестр заводских текстов в коде (подход A) |
| Разметка | HTML Telegram; подстановки `{имя}` из разрешённого списка события |
| Кастомные эмодзи | Через `<tg-emoji emoji-id="…">символ</tg-emoji>`; в боте — автоматически из присланного сообщения (`message.html_text`) |

## 4. Реестр событий

Файл `app/services/message_templates/registry.py`. Для каждого события: `key`, `group`, `title`, `trigger` (человекочитаемое описание), `default_template`, `variables` (имя, описание, пример), `required_variables`, `button` (подпись по умолчанию или нет). Тексты по умолчанию — **дословно текущие**.

| Ключ | Группа | Когда отправляется | Переменные | Кнопка |
|---|---|---|---|---|
| `payment_success` | Платежи | Платёж подтверждён (покупка, продление, автоплатёж) | `amount`, `description` | — |
| `referral_bonus` | Рефералы | Начислена реферальная комиссия | `amount` | — |
| `referral_invite_bonus` | Рефералы | Друг зарегистрировался по ссылке (+дни подписки) | `bonus_days` | — |
| `subscription_expiring` | Подписка | За 3 дня и за 1 день до окончания | `days_left` | — |
| `subscription_expired` | Подписка | Подписка истекла | — | — |
| `gift_redeemed` | Подарки | Подарок активирован (сообщение дарителю) | `who` | — |
| `gift_code_ready` | Подарки | Платёж за подарок подтверждён, код создан | `link` (обязательная) | — |
| `balance_credited` | Баланс | Админ начислил баланс | `amount`, `balance` | — |
| `balance_debited` | Баланс | Админ списал с баланса | `amount`, `balance` | — |
| `autopay_activated` | Автоплатёж | Автоплатёж подключён | — | — |
| `autopay_charge_failed` | Автоплатёж | Не удалось списать автоплатёж | — | — |
| `autopay_stopped` | Автоплатёж | Автоплатёж отключён | — | — |
| `winback` | Возврат клиентов | Через 7 дней после истечения подписки | — | «💎 Возобновить подписку» |
| `abandoned_payment` | Возврат клиентов | Оплата не завершена спустя 1 час | — | «🔁 Попробовать снова» |
| `welcome_nudge` | Возврат клиентов | Через 24 часа после регистрации без покупки | — | «🚀 Открыть приложение» |

Тексты по умолчанию (для золотых тестов):

- `payment_success`: `✅ Оплата на сумму {amount}₽ прошла успешно. {description}`
- `referral_bonus`: `🎉 Вам начислено {amount}₽ реферальных бонусов!`
- `referral_invite_bonus`: `🚀 По вашей ссылке зарегистрировался друг — начислено +{bonus_days} дн. подписки!\n\nПриглашайте ещё — бонус начисляется за каждого нового друга.`
- `subscription_expiring`: `⏳ Ваша подписка истекает через {days_left} дн.`
- `subscription_expired`: `❌ Ваша подписка истекла. Продлите её в главном меню.`
- `gift_redeemed`: `🎁 Ваш подарок активировал {who}!`
- `gift_code_ready`: `🎉 Оплата прошла успешно! Подарочный код создан.\n\nОтправьте эту ссылку тому, кому хотите подарить подписку:\n{link}\n\nКод действителен 30 дней.`
- `balance_credited`: `💰 Баланс пополнен!\n\nСумма: +{amount}₽\nТекущий баланс: {balance}₽`
- `balance_debited`: `💸 Средства списаны с баланса\n\nСумма: -{amount}₽\nТекущий баланс: {balance}₽`
- `autopay_activated`: `🔄 Автоплатёж подключён — подписка будет продлеваться автоматически каждый месяц.`
- `autopay_charge_failed`: `⚠️ Не удалось списать автоплатёж — проверьте, что на карте/счёте достаточно средств.\n\nПодписка продолжает действовать до текущей даты окончания.`
- `autopay_stopped`: `🔕 Автоплатёж отключён (банк отклонил привязку или списания подряд не проходят).\n\nПодписку можно продлить вручную в любой момент.`
- `winback`: `👋 Соскучились? Ваша подписка уже некоторое время неактивна — самое время вернуться, пока для вас держим ваш профиль и настройки.`
- `abandoned_payment`: `💳 Похоже, оплата не завершилась. Если передумали или что-то пошло не так — можно оформить заново, это займёт минуту.`
- `welcome_nudge`: `🔐 Не забыли про VPN? Пробный период уже начался — попробуйте подключиться сейчас, а когда пробный период закончится, сможете оформить подписку в один тап.`

Формат значений переменных: суммы — число с двумя знаками без символа валюты (`249.00`; знак `₽` остаётся в тексте шаблона и редактируется); `amount` в `balance_debited` — модуль суммы; `who` — `@username` либо слово `пользователь`; `description` — обычный текст из кода (экранируется).

Подпись кнопки у `welcome_nudge` по умолчанию зависит от настройки `MINIAPP_URL`: «🚀 Открыть приложение» (кнопка Mini App) либо «🚀 Открыть меню» (запасной callback). Правка подписи заменяет обе.

## 5. Модель данных

Таблица `message_templates` (миграция только добавляющая; пустая таблица = поведение как сейчас):

| Поле | Тип | Смысл |
|---|---|---|
| `key` | str(64), PK | ключ события из реестра |
| `template` | text, nullable | текст в HTML Telegram; NULL — использовать заводской текст (строка нужна, чтобы выключить событие или сменить подпись кнопки) |
| `button_text` | str(64), nullable | подпись кнопки (только события с кнопкой) |
| `enabled` | bool, default true | выключенное событие не отправляется |
| `updated_at` | timestamptz | |
| `updated_by_user_id` | FK `users.id`, SET NULL | кто изменил последним |

Строки создаются только при правке; «Сбросить» удаляет строку (и текст, и кнопку, и флаг).

## 6. Отправка сообщений

`app/services/message_templates/service.py`:

- `render_message(key, **variables) -> Rendered` — берёт шаблон из кэша (или заводской), подставляет переменные (значения экранируются как HTML) и возвращает `(text, button_text, enabled, is_custom)`.
- **Кэш:** таблица из ≤ 15 строк загружается лениво отдельной короткой сессией, обновляется не реже раза в 60 секунд и сразу сбрасывается после сохранения/сброса (API и бот в одном процессе). Сбой чтения БД → используются заводские тексты (и запись в лог).
- **Отправка** (`send_templated(bot, telegram_id, key, **variables)`, используется всеми `notify_*`):
  1. событие выключено → сообщение не отправляется, лог `notification_skipped`;
  2. отправка пользовательского шаблона; при `TelegramBadRequest` (плохая разметка, недопустимое эмодзи) → **автоматическая отправка заводского текста** и лог `template_fallback` с причиной;
  3. остальные ошибки (пользователь заблокировал бота, сеть, flood-control) обрабатываются как сейчас в `_safe_send`.
- Все сигнатуры `notify_*` сохраняются; меняются только их тела. Вызывающий код (платежи, фоновые задачи) не меняется.

## 7. Проверки при сохранении

Одни и те же для API и бота (`app/services/message_templates/validation.py`); результат — список понятных сообщений об ошибках:

1. Только разрешённые Telegram теги: `b`, `strong`, `i`, `em`, `u`, `ins`, `s`, `strike`, `del`, `a` (только `href` со схемами `https`/`tg`), `code`, `pre`, `tg-spoiler`, `blockquote`, `tg-emoji` (только `emoji-id` из цифр); теги парные и правильно вложены.
2. Только разрешённые переменные события; все обязательные переменные присутствуют (например `{link}`); нераспознанные фигурные скобки — ошибка.
3. Длина: рендер с примерами переменных ≤ 4096 символов (лимит Telegram).
4. Текст кнопки: 1–64 символа, без разметки и без кастомных эмодзи (Telegram не поддерживает их в тексте кнопки).
5. Корректность конкретного кастомного эмодзи (fallback-символ должен совпадать с «родным» символом ID) офлайн проверить нельзя: интерфейсы показывают предупреждение «проверьте кнопкой Тест», а рантайм страхуется откатом на заводской текст.

## 8. API (`/cabinet/admin/notifications/*`, `require_admin`)

| Метод и путь | Назначение |
|---|---|
| `GET /templates` | Список событий: `key`, `group`, `title`, `trigger`, `template` (текущий), `variables: string[]`, плюс аддитивные поля: `default_template`, `is_customized`, `enabled`, `button_text`, `default_button_text`, `variable_docs: [{name, description, example}]`, `required_variables`, `updated_at`, `updated_by` |
| `PUT /templates/{key}` | Тело `{template, enabled, button_text}`; ошибки проверок → `422` со списком; неизвестный ключ → `404` |
| `DELETE /templates/{key}` | Сбросить к заводскому (идемпотентно) |
| `POST /templates/{key}/preview` | Тело `{template?, button_text?}` (без сохранения); ответ `{html, length, warnings}` — тот же рендер с примерами переменных |
| `POST /templates/{key}/test` | Отправить рендер **вызывающему админу** в Telegram; при отказе Telegram — `502` с текстом причины |
| `GET /emoji` | Кастомные эмодзи из `app/emoji.py` с заданным ID: `name`, `fallback`, `custom_id` |

Поля, которые уже знает страница во фронтенде (`key, group, title, trigger, template, variables`), сохраняют имена и типы. Схемы попадают в `docs/api/` через генератор.

## 9. Редактор в боте

`/admin` → «✉️ Сообщения» (только `is_admin`; FSM-состояния `AdminTemplateStates`, как у существующих `AdminTariffStates`):

- Список событий по группам; метки ✅/🚫 (вкл/выкл) и ✏️ (изменено).
- Карточка события: текущий текст (с примерами переменных), список переменных, кнопки «✏️ Изменить текст», «🔘 Текст кнопки» (если есть), «🔔 Вкл/Выкл», «↩️ Сбросить», «📨 Тест мне», «⬅️ Назад».
- «Изменить текст»: бот просит прислать новый текст и перечисляет переменные; берётся `message.html_text` (сущности форматирования и `custom_emoji` уже превращены в HTML/`<tg-emoji>`), проходит проверки, показывается предпросмотр и «Сохранить / Отмена».
- Кастомные эмодзи в отправляемых ботом сообщениях требуют Telegram Premium у владельца бота (ограничение Telegram, см. `app/emoji.py`); без него Telegram отклонит отправку, сработает откат на заводской текст, а кнопка «Тест» покажет причину.

## 10. Тестирование

- **Золотые тесты:** для каждого из 15 событий рендер заводского текста с примерами переменных равен текущему тексту дословно; вызов каждой `notify_*` с `AsyncMock`-ботом отправляет тот же текст и ту же клавиатуру, что и до изменения.
- **Рендер:** подстановка, экранирование HTML в значениях, неизвестная/обязательная переменная, выключенное событие не отправляется, кэш сбрасывается сразу после сохранения и сброса, откат на заводской текст при `TelegramBadRequest` (ровно одна повторная отправка), сбой чтения БД не ломает отправку.
- **Проверки:** лишний тег, непарные теги, `javascript:`-ссылка, некорректный `emoji-id`, длина, подпись кнопки с разметкой.
- **API:** `TestClient` — права, `422`-формат, сброс, предпросмотр, тестовая отправка (успех и отказ Telegram), список эмодзи.
- **Бот:** обработчики с настоящими `Message` (в т.ч. с сущностью `custom_emoji`): `html_text` даёт `<tg-emoji>`, отмена, невалидный текст, доступ только админу.
- Проверка чувствительности: временные поломки (убрать экранирование, убрать откат, пропустить проверку тегов) должны ронять тесты. Существующие 199 тестов проходят без правок.

## 11. Ошибки и защита

- `notify_*` по-прежнему никогда не бросают исключение наружу.
- Любая проблема с шаблоном → заводской текст + запись в структурный лог (`template_fallback`); сохранение и сброс тоже логируются (`template_updated`, `template_reset`: ключ, админ, длина текста, без самого текста).
- Значения переменных всегда экранируются; шаблон — только разрешённые теги (нет исполняемого содержимого).
- Одновременная правка двумя админами: побеждает последняя запись.
- Запуск более чем в одном процессе: устаревание кэша ограничено 60 секундами.

## 12. Выкладка и документация

1. Миграция (одна новая таблица), деплой; поведение не меняется, пока шаблон не отредактирован.
2. Перегенерировать справочник API (`python scripts/generate_api_docs.py`) и дополнить `docs/api/API.md`.
3. Передать контракт агенту фронтенда (страница «Уведомления» **не удаляется**, она задаёт форму контракта).

## 13. Декомпозиция работ

1. Реестр, таблица, кэш, рендер, `send_templated`, перевод `notify_*`, золотые тесты.
2. Проверки при сохранении и API (`/notifications/*`), документация.
3. Редактор в боте.
4. (Отдельно, NRW-MiniApp) страница «Уведомления».

## 14. Риски и допущения

- Кастомные эмодзи работают только при Premium у владельца бота; иначе — откат на заводской текст.
- Заводские тексты дублируются в реестре и должны совпадать с прежними побайтно: защита — золотые тесты.
- События вне реестра (триал, приветствие, ответы поддержки) остаются в коде до следующего этапа.
- Тексты кнопок меню и тексты обработчиков не входят в объём.
